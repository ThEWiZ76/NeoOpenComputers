# Robot block swing: tools and protection

Upstream server/component/Agent.scala routes swing through server/agent/Player.scala clickBlock, using equipment slot 0, harvest checks, player interaction and actual tool damage. The port instead called Level.destroyBlock directly and passed two unchanged copies of the selected cargo item to damage events. This bypassed ordinary BlockEvent.BreakEvent protection and harvested tool-required blocks without the equipped tool.

RobotBlockEntity.swing now lends the equipped tool to the robot fake player in survival mode and calls ServerPlayerGameMode.destroyBlock after harvest and RobotBreakBlockEvent.Pre checks. This invokes normal block protection, loot and durability. Actual before/after tool stacks reach ComputeDamageRate and ApplyDamageRate; the changed tool returns to TOOL_SLOT. Cargo is untouched. Successful callback returns true, block. Prior fake-player hand and game mode are restored in finally. The existing barehand swing fixture now uses dirt because untooled stone harvest should fail upstream.

Evidence: robot-swing-red.log reproduces wrong harvest eligibility and absent equipped-tool damage. RobotWorldInteractionGameTests verifies iron-pick stone harvesting, one durability point, exactly one cobblestone, cargo preservation, callback result, refusal to harvest diamond ore using only a cargo pickaxe, and canceled standard block-break event preserving block/tool. Full test build runGameTestServer: robot-swing-protection.log, 2057 unit tests zero failures/errors and all 456 required GameTests. git diff --check clean; no workflows in HEAD or origin/develop.

The same run also verifies robotBootsOpenOsAndRunsBundledGoAfterPickup: assembler-created robot with BIOS and full copied OpenOS HDD boots upstream init (only interactive loop replaced), loads robot ROM, runs go left, writes /home/pickup.txt, breaks via standard Level.destroyBlock, drops one assembled item, places via BlockItem, stays stopped until explicit start, boots OpenOS again, reads the earlier file and runs go again. This tests boot/persistence; the HDD fixture copies bundled OpenOS files and does not exercise the interactive install command. Initial test setup incorrectly asserted mkdir on existing /home; corrected to create only when missing.
