# Native Lua argument conversion

Runtime 2fa780a7e0b44771ec3130aa26e97814fbf78333; verified 2026-10-20. Continues [[Native Lua outgoing values]]. Shared decoder callers are native component.invoke and userdata apply/unapply/call/invoke.

Upstream util/ExtendedLuaState.scala toSimpleJavaObject maps function/thread arguments to null; table conversion goes through JNLua's Map view. The existing LuaJ snapshot decoder already handles shared/cyclic table values. NativeLuaValues instead threw for functions/threads, copied shared child tables and descended into cycles until the guard rejected them. The native decoder now uses a per-argument Lua-table-pointer memo to build detached Java maps and maps unsupported values to null. Memo lookup precedes the new-descent depth guard, so back-references close cycles; noncyclic excessive nesting is still rejected. Existing table finally blocks preserve the entry Lua stack, and no Lua proxies/registry roots escape into callback arguments.

Binary table keys previously were unconditionally decoded as UTF-8. Keys FF and FE both became the replacement character, silently overwriting one value. Valid UTF-8 keys retain their existing String representation; other keys stay byte arrays after an exact byte-for-byte UTF-8 roundtrip check. The bundled JNLua DefaultConverter bytecode also retains non-text string bytes rather than forcing all keys into text. This fix avoids binary collisions without changing ordinary text keys, scalar numeric handling or binary argument values. Persistence and outgoing-value code are unchanged.
