## Immediate filesystem handle restoration —cb34eac02

DirectoryFileSystem.save/load previously did nothing. A regression saving open binary input/output handles fails1/38 focused tests because the restored input handle is absent. save now records input/output handle IDs, paths relative to the filesystem root and exact positions, plus capacity.used. It does not close live handles. load closes previous streams and restores valid existing files with preserved IDs/positions and non-truncating rw access for saved outputs. New IDs avoid restored handles. Missing files, invalid paths/IDs/positions and duplicate IDs are skipped; restoring a missing output never creates it.

## Buffered saves and actual JVM restart —cbda79eab6be645406338f058e0fbb4f2c92b587

This supersedes the earlier buffered=true unimplemented status. FileSystemRegistry now selects BufferedFileSystem for true and the immediate DirectoryFileSystem for false. BufferedFileSystem reuses the existing memory filesystem and its stream serialization. A save freezes a deep copy of file bytes/tree/handles and queues disk IO on one daemon worker; subsequent mutations cannot alter a queued snapshot. Host NBT contains input/output metadata and capacity.used, not another full file tree. Loading reads committed files from disk and stream IDs/offsets from NBT. Creating/loading another instance waits behind already-queued IO; close waits for its queued saves and closes streams without committing unsaved mutations. ServerStopped drains the IO queue.

File writes use same-directory temporary files and atomic replacement when supported, with ordinary replacement fallback. Rename destinations are written before their old source paths are removed. A conflicting externally changed destination reports a failed save, preserving its data and the durable rename source; pending failure also surfaces on load/close. Cleanup removes only tracked unchanged files and empty tracked directories, preserving unrelated files created on disk. Disk IO rejects symlinks at the filesystem root or inside it rather than traversing them. This is not a filesystem-wide atomic transaction or crash-mid-save guarantee. Reopening after a save failure reads the actual on-disk state; do not silently treat the failed save as successful.

Both immediate and buffered modes now include upstream file/directory entry costs in spaceUsed and enforce quota at directory/file creation and file growth. Loading existing buffered contents bypasses creation quota, preserving data even when it exceeds the current limit. The direct-persistence fixture now uses4096 bytes instead of an invalid128-byte capacity below the default512-byte root entry cost.

Two additional shared-memory correctness fixes protect buffered and RAM filesystems: a second writer cannot truncate an active writer's file, and deletion cannot orphan a live output handle; closing releases the writer. Renaming a directory into its own descendant is rejected, and renaming a path onto itself is a no-op. Existing native disk paths/backends were not replaced. No automatic migration or removal of prior process-relative files was added.

## Buffered filesystem case policy - 2026-10-20

Runtime `3babca34672ca4caae7c1c3a91e3188433282404` restores upstream buffered filesystem case behavior. Buffered mounts detect the actual host policy; `filesystem.forceCaseInsensitiveFS` defaults to false and forces insensitive lookup when enabled. Existing names keep their spelling, and case-only rename is a no-op. Lookup, creation, append, rename, deletion and restored stream paths resolve existing names per directory using Locale.ROOT lowercase, matching the upstream lowercase approach. Ordinary API fromMemory remains case-sensitive.

Two aliases cannot open independent writers or truncate an active writer. A tree with case-colliding sibling names is rejected before replacing the current tree or handles. Buffered reload validates disk contents before closing streams or replacing its checkpoint. Host probing removes its own file and restores the directory timestamp only when direct entry fingerprints are unchanged; this is not a cross-process transaction or exhaustive Unicode/platform proof.
