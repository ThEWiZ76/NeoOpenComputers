# ComputerCraft media and diskdrive persistence

Checkpoint a6f0c3905487863bcbaad501506c8af137914766, 2026-10-20. CC:Tweaked1.120.2 / Minecraft1.21.1 / NeoForge21.1.234 / Java21. Related: [[../Project]], [[../02 plans/ComputerCraft integration]], [[ComputerCraft peripheral integration]], [[Process restart test]].

MediaDriver uses the public NeoForge MediaCapability, matching CC's own lookup. Modern native disks do not implement IMedia on the Item; the old instanceof rule would miss them. The optional driver keeps the original floppy slot/tier0 contract and creates environments only with an actual ServerLevel. Native media supplies its mount, label and disk ID; MountFileSystem supplies OC channel semantics. A new OC node address is written to the actual stack before publishing the filesystem. Environment save writes OC state back without replacing other item components. Native ID allocation and successful label changes mark the host dirty; immutable labels report an error. Audio/non-data media has no invented filesystem.

Two host bugs were exposed and fixed. DiskDriveBlockEntity did not save its stack-backed environment before split/take/replacement/clear, losing a floppy's identity and current state on removal. It now saves before those inventory mutations; existing block destruction already saved before dropping contents. Actual restart then failed because loadAdditional runs before the ServerLevel is assigned: CC media could not open its native mount and the disk environment was absent on onLoad. Pending saved state is retained, including saves made before initialization, and retried on server onLoad before network publication. Ordinary already-created environments keep their existing path.

Five new server regressions cover all four ordinary OC-floppy removal paths with stable identity and exact0/128/255 data; actual native Lua5.3 OC diskdrive/case access to a real CC disk, Unicode label and binary/UTF-8 bytes; item encoding/reinsertion/native CC API readback; a tagged capability-only readonly medium using CC's actual ROM resource mount; immutable label rejection, audio/null-host behavior; and loading block data before assigning its world. Native treasure Lua assets are absent in the pinned published artifact, so the readonly test does not claim a real treasure disk program ran. Client-side environment behavior still needs client acceptance.
