## Import protocol

NativeVolumeStore(worldRoot).openManaged(data, capacity, buffered) takes a copy of the existing driver/environment tag. It returns a Mount with relative storageRoot, unchanged nodeAddress (or a generated address only when absent), and an existing direct/buffered FileSystemRegistry filesystem. Callers must persist that binding in fs.oc:storage and use the returned address during later runtime wiring; this helper does not modify the original item/host tag or construct a component environment.

Lowercase UUID addresses use their conventional world/opencomputers/<uuid> directory. Other legacy addresses retain their visible identity while using native-legacy/<SHA-256> below that world root. Saved bindings accept only those two root forms. This avoids path traversal/case aliasing from arbitrary node strings and lets a binding survive later node-address remapping. Managed formatting already removes the fs tag; runtime wiring must preserve that rule for the new binding.

Inline fs.children trees are validated before publication: actual RAM serialization has an implicit root directory, while child entries carry isDirectory; duplicate/invalid names, malformed data/child/root metadata and invalid bindings fail explicitly. Import files are staged outside the mounted tree, flushed, and moved without REPLACE_EXISTING. Existing nonidentical/foreign files or occupied destinations refuse the import. An already-identical complete directory can be adopted without rewriting its files or timestamps. No unrelated files, source NBT or legacy archives are deleted.

Version1 pending/complete compressed NBT journals in opencomputers/.native-imports contain the relative root and a canonical SHA-256 of sorted source paths/types/bytes/timestamps. A pending import may add missing entries only when all existing paths match its original source; a completed import makes disk contents authoritative and never replays stale inline bytes. Journal corruption, a different inline generation, missing bound/completed volumes and missing recovery source fail closed. One JVM lock serializes mount/import setup; normal mounted IO uses the existing backend. Root/path link checks and bounded journal parsing protect the import boundary; this is not a claim of adversarial cross-process or universal junction/filesystem crash safety.

Backend load/save still owns stream restoration. Both direct/buffered tests restore input/output IDs and positions from old metadata without truncation, and new backend snapshots contain metadata rather than children. Label/lock/owner policy remains the native factory's responsibility in the following stage.

## External compressed raw drives - 2026-10-20

Runtime `6cf4c2890fe2b2869fa5d84d70abe9cdbb2b804a` completes the native raw backend switch. Upstream server/component/Drive.scala stores a GZIP stream under opencomputers/<node>.bin. NativeVolumeStore.openRaw uses that binary format and conventional UUID.bin path; non-UUID legacy identities retain their visible ID and use native-legacy/<sha256>.bin. Driver metadata stores oc:rawStorage independently of later node-address remapping. Host/item saves omit data bytes and retain node, label, raw mode, lock owner and headPos. Raw saving is synchronous at host-save time (including serialized disk IO and forced temporary file); filesystem.bufferChanges continues to select managed HDD/floppy/RAID behavior, not raw per-byte writes.

Old inline data is imported before mounting without mutating the source. Pending/complete journals share the bounded .native-imports mechanism, keyed by the raw filename and source-byte digest. Matching existing upstream GZIP files are adopted without rewriting bytes/mtime. Matching pending publications resume; conflicts, missing bound/completed files, malformed metadata, invalid bindings and invalid/truncated GZIP fail explicitly. Completed imports keep disk contents authoritative rather than replaying old inline bytes. The loaded raw image must fit the configured capacity; smaller images are zero-padded in the drive, larger images are rejected rather than silently truncated. This is a deliberate data-preserving limit, not full capacity-shrink compatibility.

Raw sessions retain compressed/content digests rather than an extra permanent full image. Saving checks the current file against the mounted fingerprint, so another session/copy/external writer cannot silently be overwritten. Explicit reload accepts a valid current disk image and resets the baseline; unchanged images preserve file bytes/mtime. Saves publish a same-directory temporary GZIP file with atomic replacement where supported and an ordinary replacement fallback. No cross-process compare-and-swap, directory-fsync/powerloss or whole-world transaction guarantee. Disk IO shares the managed buffer worker; a mount is never inspected halfway through one of its own queued publications.

DiskItemEnvironment injects the actual active-world mount; both raw and managed native factories require an active server. There is no serverless native RAM fallback. The old standalone DriveEnvironment constructor remains explicit inline memory storage for isolated component tests; it refuses external-storage metadata without a mount. Native loads validate/read the disk before replacing bytes/node/label/head. Later inline metadata must match the mount's known import origin (including a completed journal's original source); an unknown/different late payload fails instead of being silently ignored. This does not reconcile arbitrary inconsistent historical host/item snapshots. A real mode format clears oc:rawStorage with old node/fs/bytes/head/owners, while a same-mode operation preserves the binding. Old unreferenced volume files are not automatically garbage-collected.

Three preexisting raw-state defects are fixed: standalone NBT snapshots clone the byte array; loading shorter data clears the old tail; valid headPos is clamped to sectorsPerPlatter-1 rather than sectorToHeadPos(sectorCount), which reset normal heads to0. Raw label/IO/load/save methods synchronize on the drive, matching upstream snapshot exclusion. Signed readByte(0xff) remains -1; sector/platter/capacity/timing callbacks otherwise keep their existing contracts.

## Storage failures at actual host boundaries - 2026-10-20

Block and rack diskdrives retain a copied pending media snapshot until restoration succeeds or the slot changes. Normalization writes detached item data, so an older item snapshot is not mutated. Healthy replacement or repaired array backing can be mounted through the normal reload/item-change paths.
