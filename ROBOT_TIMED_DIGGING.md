# Robot timed digging and world-read threading

Upstream server/agent/Player.scala clickBlock derives dig duration from hardness * 1.5 / grounded-player dig speed * robot.delays.harvestRatio, permits RobotBreakBlockEvent.Pre adjustments, and schedules DamageOverTime while the agent runs. The port destroyed the target immediately.

RobotBlockEntity now queues one transient DigTask, pauses the caller for adjusted duration, and advances it on server ticks before machine.update. Duration is at least one tick; config robot.delays.harvestRatio defaults to 1. Tool speed uses the fake player's getDigSpeed while temporarily grounded, as upstream does. Unique negative breaker ids drive vanilla crack-progress updates. Completion rechecks tool/target/origin/loaded status/running state and invokes the existing survival player harvest path. Stop, changed block or tool, relocation/removal and unload cancel pending work and clear cracks. A stopped robot cannot start a dig. GameMode can return true for a block refusing removal, so Post is emitted only if target state changed.

Tests use a running CPU/RAM/EEPROM robot and controlled calls to the normal server ticker. Event-adjusted .5 seconds leaves stone after nine ticks and removes it at ten; iron pick on stone with ratio 2 completes at fifteen ticks. Changed target and stopped machine keep blocks and tool intact. Existing protection test now observes the actual BlockEvent at completion; prior wear tests finish queued work before assertions, restoring config/listeners in finally. No wall-clock timing assertions.

The real EEPROM end-to-end test exposed an existing deadlock in robot.detect: direct=true executes world getBlockState from LuaThread, ServerChunkCache waits on server, server waits on LuaThread.resume. Evidence robot-dig-threads.txt shows Server thread waiting in LuaThread.State.lua_resume and Coroutine-54 waiting in ServerChunkCache.getChunk via RobotBlockEntity.detect. That specifically identified hung test server was terminated; it was not restarted merely for a polling timeout. detect and compare both read world state and now use synchronized callbacks. EEPROM test calls compare, swing, detect and sets sentinel light only after the block is gone. It now passes.
