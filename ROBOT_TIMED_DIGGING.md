Upstream server/agent/Player.scala clickBlock derives dig duration from hardness * 1.5 / grounded-player dig speed * robot.delays.harvestRatio, permits RobotBreakBlockEvent.Pre adjustments, and schedules DamageOverTime while the agent runs. The port destroyed the target immediately.

RobotBlockEntity now queues one transient DigTask, pauses the caller for adjusted duration, and advances it on server ticks before machine.update. Duration is at least one tick; config robot.delays.harvestRatio defaults to 1. Tool speed uses the fake player's getDigSpeed while temporarily grounded, as upstream does. Unique negative breaker ids drive vanilla crack-progress updates. Completion rechecks tool/target/origin/loaded status/running state and invokes the existing survival player harvest path. Stop, changed block or tool, relocation/removal and unload cancel pending work and clear cracks. A stopped robot cannot start a dig. ## Dig tool swing animation

Robot dig now starts an equipped-tool swing and sends the swing flag using the existing restricted animation update payload. Upstream Robot.setAnimateSwing minimum five ticks and RobotRenderer repeated sine arc are reproduced: cycles=max(total/10,1), integer ticksPerCycle=total/cycles, angle=sin(fraction(remaining/ticksPerCycle)*pi)*45 degrees. Renderer applies X rotation only inside the equipped tool pose. Move/turn clear the swing flag.

Dig cancellation clears active swing and synchronizes the stop. Successful completion clears only the dig/crack state, allowing short digs to finish the minimum five-tick animation. No client machine execution or private hardware data added to packets.
